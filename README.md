# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные приложения

### Интерфейс IProduct
- `id` - Хранит уникальный идентификатор товара в виде строки
- `title` - Хранит имя товара в виде строки
- `description` - Хранит описание товара в виде строки
- `category` - Хранит категорию товара в виде строки
- `price` - Хранит стоимость товара в виде числа или ноля
- `image` - Хранит название изображения для карточки товара в виде строки

Задает структуру данных для объектов товаров и массивов их содержащих

### Интерфейс IBuyer
- `payment` - Хранит выбранный способ оплаты в виде уникального значения
- `address` - Хранит адрес пркупателя в виде строки
- `email` - Хранит почтовый ящик покупателя в виде строки
- `phone` - Хранит номер телефона покупателя в виде строки

Задает структуру данных для объектов заказов

### Интерфейс IApi
- `get<T extends object>(uri: string)` - Выполняет GET запрос по указанному URI и возвращает Promise с данными типа T
- `post<T extends object>(uri: string, data: object, method?: ApiPostMethods)` - Выполняет POST запрос с данными и возвращает Promise с ответом типа T

Определяет контракт для классов, выполняющих HTTP-запросы

### Интерфейс IOrderRequest
- Наследует все поля интерфейса `IBuyer`
- `total` - Хранит общую стоимость заказа в виде числа
- `items` - Хранит массив идентификаторов товаров в виде строк[]

Задает структуру данных для отправки заказа на сервер
### Интерфейс IProductsResponse
- `total` - Хранит общее количество товаров в виде числа
- `items` - Хранит массив товаров типа `IProduct[]`

Задает структуру ответа сервера на запрос списка товаров

### Интерфейс IOrderResponse
- `id` - Хранит уникальный идентификатор созданного заказа в виде строки
- `total` - Хранит итоговую стоимость заказа в виде числа

Задает структуру ответа сервера на создание заказа

### Общее назначение
Интерфейсы отвечают за: 
- Валидацию структуры - гарантируя, что объект имеет нужные поля правильных типов
- Автодополнение - IDE подсказывает доступные свойства и методы
- Читаемость кода - явно показывает, какие данные ожидаются
- Переиспользование - один интерфейс можно применять к множеству объектов

## Модели данных

+ Сеттер `setTargetProduct` принимает объект товара типа `IProduct` и устанавливает его значением поля `targetProduct`
+ Геттер `getTargetProduct` проверяет данные в поле `targetProduct` и, если поле не пустое, возвращает объект записанного в него товара типа `IProduct`

- Хранить данные каталога товаров на главной странице

+ Получать данные из каталога
+ Получать товар по его `id`
+ Сохранять информацию о выбранном товаре
+ Получать данные о выбранном товаре

Отвечает за:
- Хранение товаров, которые пользователь выбрал для покупки

Позволяет:
- Хранить список и данные товаров в корзине
+ Получать список товаров в корзине

+ Вести счетчик товаров в корзине
+ Проверять наличие товара в корзине

## Слой коммуникации

### Запросы Api

#### Получить весь список товаров: 
` GET https://larek-api.nomoreparties.co/api/weblarek/product/ `
- При успешном запросе `200 ОК` возвращает объект:
```
{ 
    "total": number,
    "items": productItem[] {
        ...{
            "id": string,
            "description": string,
            "image": string,
            "title": string,
            "category": string,
            "price": number | null
        }
    }  
} 
```

#### Получить один товар: 
` GET https://larek-api.nomoreparties.co/api/weblarek/product/${pruduct.id} `
- При успешном запросе `200 ОК` возвращает объект с указанным в запросе id:
```
{
    "id": string,
    "description": string,
    "image": string,
    "title": string,
    "category": string,
    "price": number | null
}
```
- При ошибке `404 Not Found` возвращает объект с указанием ошибки:
``` 
{
    "error": string
} 
```
#### Отправить информацию о заказе: 
` POST https://larek-api.nomoreparties.co/api/weblarek/order `
- При успешном запросе `200 ОК` возвращает объект:
```
{
    "id": string,
    "total": number
} 
```
- При ошибке `400 Bad Request` возвращает один из объектов с указанием ошибки:
``` 
{
    "error": string
} 
```

### Класс MApi
- `api` - Хранит объект, реализующий интерфейс `IApi`
- Конструктор принимает объект типа `IApi` и сохраняет его в поле `api`
+ Метод `getProductList` выполняет GET запрос на эндпоинт `/product/`, преобразует ответ и возвращает Promise с массивом товаров типа `IProduct[]`
+ Метод `createOrder` выполняет POST запрос на эндпоинт `/order/` с данными заказа и возвращает Promise с ответом сервера типа `IOrderResponse`

Отвечает за:
- Взаимодействие с Api сервера "Веб-ларёк"

Позволяет:
- Получать список товаров с сервера
- Отправлять данные заказа на сервер
- Инкапсулировать логику работы с Api эндпоинтами

### Общее назначение
Слой коммуникации обеспечивает:
- Типизацию всех запросов и ответов Api
- Централизованное управление взаимодействием с сервером
- Изоляцию HTTP-логики от бизнес-логики приложения
- Единую точку для модификации Api-запросов
